# AEGIS — Chart Precision and Analytical Consistency Review

Baseline: AEGIS_Online_Integrity.zip and AEGIS_Windows_Integrity.zip. The reviewed source was extracted from these actual archives. Shared engine changes were synchronized between both editions; portable-specific functionality was retained.

## Findings and corrections

1. Custom chart values were rounded to eight decimal places, and automatic quantity/amount charts to two places. This could turn small nonzero measurements into zero or invent ties. Group calculations now use Decimal, preserve exact values in evidence, and convert to renderer numbers only at the display boundary. Custom charts reject distinct values that collapse at rendering precision (including sampled scatter coordinates); automatic charts with such collisions or nonzero-to-zero conversion are omitted with an explanatory warning. Histograms retain distinct numeric range labels. The local browser labels use scientific notation for small nonzero values; zero bars no longer receive a misleading artificial minimum height. Chart interpretation and dataset summaries preserve small values rather than rounding them to zero. Decimal arithmetic remains finite-precision, not arbitrary-precision symbolic math.
2. Standard grouped query rankings formerly converted Decimal results to floats before sorting and tie expansion. They now compare Decimal values first and serialize afterward; exact noninteger values that cannot round-trip through a JSON float are returned as decimal strings. A checked exact result can therefore be textual numeric evidence, not a rounded machine number.
3. Automatic amount-by-group charts and inferred numeric distributions, as well as focused numeric field profiles, bypassed the shared currency/identifier guard. All these paths now use the common measure check. Mixed/missing/ambiguous recognized currencies are not aggregated. Identifier-like account fields are profiled as categories, not averaged. Unspecified currency is still explicitly unspecified; no currency or exchange rates are invented. Conventional repeating averages in profiles are rounded for readability and labeled as rounded.
4. Automatically inferred semantic roles previously selected the first alias even when multiple candidate headers existed. Ambiguous alias matches are no longer silently selected; manager mappings still take precedence. Generic numeric inference remains available with source-column labeling and measure validation.
5. A synthetic remainder category could collide with a genuine category called Other categories and could become the alleged highest individual group. Remainder labels are now distinct, marked explicitly, and excluded from individual-group extrema in selected charts and chart catalogs. Their values still contribute to the displayed total when calculating applicable shares. The chart and overview describe displayed groups, not necessarily every source group.
6. Hosted SQL previously allowed some nested wrappers to circumvent identifier and raw-text numeric checks. aegis_num now accepts only a single original source column (optionally parenthesized); recognized identifier conversion is refused. Tested COALESCE/IFNULL/NULLIF and text-transform wrappers around raw text in numeric aggregates are rejected instead of coercing invalid text to zero. This conservative token-based safeguard can reject some otherwise valid expressions and is not a complete SQL semantic verifier.
7. Fractional Excel serial dates on the fictitious 1900-02-29 were converted to real dates. The entire serial range [60,61) in the 1900 system is invalid. Invalid date-styled values are blanked at import with an explicit warning; unstyled numbers remain unchanged. Custom chart year/day/month labels and automatic monthly labels use zero-padded ISO calendar years. No workbook formulas are executed.
8. The online workspace version has advanced to invalidate stale backend objects following deployment.

## Verification method

New shared module: AEGIS_App/tests/test_precision_currency_review.py (15 tests). The earlier suites were retained. The new tests cover tiny values, precision collisions, exact group ranking, currency safeguards, identifier profiles, remainder collisions and interpretation, ambiguous headers, nested SQL checks, fractional Excel dates and actual XLSX import, zero-padded dates and histogram labels.

The final verification record is FINAL_VERIFICATION.txt. Research source bytes and the frozen Windows source manifest are checked independently against the baseline. No live Groq or Ollama key was used. No Streamlit browser or clean Windows machine execution is claimed. Research only; no guarantee of arbitrary AI answer accuracy, unlimited query/chart support, or operational certification.
